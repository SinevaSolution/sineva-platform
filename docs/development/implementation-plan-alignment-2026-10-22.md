# Implementation plan alignment

## Scope and sources

This review compares the platform checkout with the workspace-level `docs/implementation-plan/README.md`, `00-conventions.md`, `M0-foundations.md` and `M1-chat-core.md`. The plan folder is outside this repository. No sineva-ai source was changed or audited, and no Linear status was changed.

The workspace-level plan checkpoint is an older snapshot. Its pending SSE work is already implemented on the platform. Its Better Auth direction is superseded by the Founder's custom JWT decision recorded in the platform checkpoint and accepted identity ADRs. The plan's statements about missing CI integration tests and destructive `docker:down` are also historical: CI has an integration job, and `docker:down` keeps volumes. This review preserves the current implementation rather than reintroducing those old patterns.

“Implemented” means code exists with local evidence. “Partial” means some acceptance criteria remain. Neither term closes a milestone. A functional screen and a passing component test do not establish the plan's browser, accessibility or cross-service gates.

## Work completed during this review

- Reviewed the incoming Library, Inbox and Members changes; their initial component suites passed 30 tests.
- Added failing-first Library regressions for a partial batch failure and per-file progress. The queue continues after a failed file, keeps successful rows and retries only failed rows. Dialog-owned sessions reuse upload tickets after PUT failures and retry completion without resending uploaded bytes. File removal is disabled during upload; scope is locked after upload starts.
- Added failing-first Inbox regressions for browser/dialog shortcut interference and lost pagination. Both behaviors now pass.
- Replaced the documentation's premature “completed” labels with the acceptance gaps above.
- Patched the Node runtime baseline for CVE-2026-111497; see the security report.
- Began WP-M0-41 before further feature expansion because it is the browser acceptance dependency for the existing screens. Its first browser run found a real dark danger-button contrast failure; the app-only foreground token and both-theme regression coverage now address it without editing compro tokens. The rerun passed all 36 scenarios.
