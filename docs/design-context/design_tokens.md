# Design tokens

Source of truth for values: `sineva-compro/docs/design/tokens.md` and its CSS. The platform vendors that CSS ([ADR-0027](../decisions/0027-design-token-source-and-vendoring.md)). If this document and the CSS in `packages/ui/src/styles/` disagree, the CSS wins and this document is wrong.

"Current" is what the code does. "Target" is decided but not built.

## Gotchas first

- **Never edit the vendored files** (`tokens.css`, `theme-dark.css`, `product-accents.css`). They are generated by `npm run tokens:sync --workspace=@sineva/ui -- <path-to-sineva-compro>` and a drift test (`packages/ui/src/__tests__/ui-tokens.test.ts`) fails when they stop matching `tokens.snapshot.json`. A value change lands in compro first.
- Compro overrides Tailwind's default scales on purpose. `rounded-xs` is 6 px, `rounded-sm` 10, `rounded-md` 14, `rounded-lg` 20, `rounded-xl` 28 (marketing), `shadow-*` and `ease-*` are compro's, and `2xl` is 1440 px. Do not carry Tailwind-default intuition over (`rounded-xl` is not 12 px here).
- Semantic names are compro's: `text-text`, `text-text-secondary`, `border-border`, `bg-action-primary`, `bg-canvas-alt` (the **app background**; `bg-canvas` is white and used by auth and Focus mode). The old platform names (`fg`, `line`, `primary`, `sidebar`, `surface-alt`, `hover`, `selected`) are gone.
- There is no `dark:` anywhere (lint bans it). Dark mode swaps the semantic variables under `:root[data-theme='dark']`; a component that uses only semantic tokens is correct in both themes without a dark rule.
- Brand teal `--teal-500` (`#00949B`) is 3.68:1 on white: non-text only (icons, rings, large text). Text uses `--color-text-brand` (`--teal-700`, 6.56:1).
- Hover and pressed are overlays (`--state-hover`, `--state-pressed`), used as `bg-(--state-hover)`. Do not use `canvas-alt` as a hover color: it is invisible on pages that already sit on it.
- z-index comes from `--z-*` (`z-(--z-modal)`); an arbitrary `z-[n]` fails lint.

## Files

| File | Owner | Contents |
| :--- | :--- | :--- |
| `packages/ui/src/styles/tokens.css` | vendored from compro `globals.css` sections 1 and 2 | Primitives and non-utility tokens in `:root` (palette, gradients, spacing, layout, surface effects, motion durations), semantic tokens in `@theme static` (colors, fonts, type scale, breakpoints, radius, shadows, easing) |
| `packages/ui/src/styles/theme-dark.css` | vendored | Semantic swaps and theme-dependent layer 3 values under `:root[data-theme='dark']` |
| `packages/ui/src/styles/product-accents.css` | vendored | The 6 compro accent ramps and the shared alias block (`--accent-surface`, `--accent-tile`, `--accent-text`, `--accent-glow`) |
| `packages/ui/src/styles/product-accents-proposed.css` | platform | The 7 proposed ramps (`desk`, `write`, `shop`, `guard`, `tax`, `legal`, `ops`). Not in compro, so they cannot sit in the vendored file. Official contrast test pending (OQ-UX-04) |
| `packages/ui/src/styles/app-density.css` | platform | Adds what compro lacks: z-index scale, content widths, `--state-hover`/`--state-pressed`, `--color-warning*`, `--color-scrim`, app type scale, focus halo, Room scene and auth scene tokens. Never redefines a compro token |
| `packages/ui/src/styles/tokens.snapshot.json` | generated | Compro commit and every custom property per file, for the drift test |
| `apps/web/src/app/globals.css` | platform | Imports `tailwindcss` and then the style files in order (tokens, dark, accents, proposed accents, app density), `@source` for `packages/ui`, base styles, motion keyframes |

## Layers

| Layer | Contents | Where |
| :--- | :--- | :--- |
| 1 Primitive | Raw palette (`--teal-*`, `--ink-*`, `--sun-*`, `--aqua-*`, `--red-*`, `--green-*`, `--amber-*`, `--white`) | `:root` in `tokens.css`. Components never use a primitive directly |
| 2 Semantic | `--color-*` | `@theme static` in `tokens.css` (light), swapped in `theme-dark.css` |
| 3 Everything else | spacing, gradients, motion durations, surface effects, z-index, widths, state overlays | `:root` (read with `var()` or `bg-(image:--x)`) |

Components reference layer 2 or 3 (R-30). No component writes a hex or `rgb(` value.

## Colors

Light and dark values and contrast ratios are in compro `tokens.md` sections 1.3 and 1.5. The test `ui-tokens.test.ts` re-asserts them. Summary of what the app uses:

| Use | Token (utility) |
| :--- | :--- |
| App background | `--color-canvas-alt` (`bg-canvas-alt`) |
| Panels, inputs, menus | `--color-surface` (`bg-surface`) plus `shadow-sm` or a border |
| Selected, user bubble, tint | `--color-surface-tint` |
| Text | `text-text`, `text-text-secondary`, `text-text-tertiary`, `text-text-brand`, `text-text-inverse` |
| Borders | `border-border` (decorative), `border-border-strong` (dividers), `--color-border-input` (control boundary, 3:1) |
| Action | `bg-action-primary`, `bg-action-primary-hover` (white text). The only action color |
| Focus | `--color-focus` (`outline-focus`, `border-focus`), 2 px outline with 2 px offset |
| Feedback | `danger`, `danger-surface`, `success`, `success-surface`, `warning`, `warning-surface` |
| Tooltip, inverse | `--color-surface-inverse` |
| Modal and drawer veil | `--color-scrim` (text color at 40% in light, a dark veil in dark) |

Specialist accents: put `data-product-accent="<key>"` on a wrapper and read only `--accent-surface`, `--accent-tile`, `--accent-text`, `--accent-glow`. Accents identify, they never act: no button, link, tab, toggle, selection or focus color, and `-500` is never text. The old `--accent-people` style variables and `accent_token` are replaced by `accent_key` (a fixed enum; the data model change is WP-M0-31).

## Radius, shadow, spacing, motion

| Token | Value | Use |
| :--- | :--- | :--- |
| `rounded-xs` / `sm` / `md` / `lg` | 6 / 10 / 14 / 20 px | badges and checkboxes / buttons, inputs, nav items / menus, popovers, toasts / panels, cards, dialogs |
| `shadow-xs` .. `shadow-lg` | compro, ink-tinted (black based in dark) | inputs / panels / popovers and hovered cards / dialogs and drawers |
| `--shadow-focus-halo` | 4 px ring of `--color-focus` at 14% | the halo a text field or the composer draws on focus |
| `--space-*` | 4 px base | plain properties; Tailwind `p-4` still uses its own `--spacing` |
| `--ease-out`, `--ease-out-expo`, `--ease-in-out` ... | compro | work mode uses `--ease-out` |
| `--dur-instant` .. `--dur-scene` | 60 / 160 / 240 / 360 / 520 / 1000 ms | 240 ms is the maximum in work mode |

## z-index

`--z-base` 0, `--z-raised` 1, `--z-sticky` 10, `--z-nav` 20, `--z-dropdown` 40, `--z-drawer` 60, `--z-modal` 100, `--z-toast` 110, `--z-tooltip` 120, `--z-skip` 130, in `app-density.css`. Strictly increasing (tested). Negative stacking inside an isolated scene (`-z-10`) is fine.

## Typography

| Role | Font | Variable | Loaded by |
| :--- | :--- | :--- | :--- |
| UI and display | Plus Jakarta Sans (variable) | `--font-plus-jakarta-sans`, exposed as `--font-sans` | `next/font/google` in `apps/web/src/styles/fonts.ts` (`latin` and `latin-ext`, `display: swap`, no `weight` option) |
| IDs, timestamps, numbers | Geist Mono | `--font-geist-mono`, exposed as `--font-mono` | same |

`.variable` of both fonts sits on `<html>` in `app/layout.tsx`. Font budget 120 KB: do not add a `weight` array (it makes next/font ship one file per weight). App type scale (`app-density.css`): `text-app-title` 24/32, `text-app-section` 18/26, `text-app-card` 15/22, all weight 600; body is 15 px. Compro's display and marketing sizes stay unused in work mode.

## Theme mechanism

`<html data-theme>` is set before the first paint by an inline script (`THEME_SCRIPT` in `packages/ui/src/lib/theme.ts`, rendered by `ThemeScript` in `app/layout.tsx` with the CSP nonce). The first visit follows the OS; a choice is stored under `sineva-theme`. `useTheme` (`client/lib/use_theme.ts`) reads the attribute and writes it through `applyTheme`; `ThemeFollowSystem` keeps following the OS while there is no stored choice. `next-themes` is not used.

Target: after sign-in the choice is also stored in `user_preferences.theme` (WP-M0-36); this change only owns the local half.

## Adding or changing a token

1. Does compro have it? Change compro's `docs/design/tokens.md` and CSS first, then run the sync script and review the diff. Never hand-edit a vendored file.
2. Is it app-only (compro has no equivalent)? Add it to `app-density.css`, with a dark value under `:root[data-theme='dark']` in the same change if it is a color. Do not redefine a compro token there (a test fails).
3. Compute contrast for every text pair it creates, in both themes. Normal text 4.5:1, non-text 3:1. Add the pair to `ui-tokens.test.ts`.
4. Use it as a utility or `var(--token)` in components. Hex, `rgb(` and `hsl(` are banned in `src/client` and `packages/ui` outside `styles/*.css` (lint and `ui-tokens.test.ts`).
5. Update this document.
